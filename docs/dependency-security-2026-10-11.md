# Python bağımlılık güvenliği — 11 Ekim 2026

Fabrika öncesi laboratuvar sürümünde `requirements.txt` Python 3.11 ortamında tüm dolaylı bağımlılıklarıyla `pip-audit 2.10.1` kullanılarak tarandı. Önceki `ortools==9.14.6206` sürümü `protobuf==6.31.1` aralığını gerektiriyordu; bu sürüm [GHSA-7gcm-g887-7qv7 / CVE-2026-0994](https://github.com/advisories/ghsa-7gcm-g887-7qv7) kapsamındadır. `ortools==9.15.6755` ve `protobuf==6.33.6` ile çözülmüş bağımlılık ağında araç **bilinen danışma kaydı bulmadı**. CI her PR ve main gönderiminde `--strict` taraması yapar; sonuç, tarama anındaki danışma veritabanına bağlıdır.

**Kalan upstream sınır:** Protobuf bakımcılarının [#26432](https://github.com/protocolbuffers/protobuf/issues/26432) kaydı, `Struct`/`Value` JSON ayrıştırmasında benzer derinlik sınırı atlamasını bildirir. [Düzeltme 21 Nisan 2026'da main'e alındı](https://github.com/protocolbuffers/protobuf/pull/27007); burada kullanılan 6.33.6 paketi 18 Mart'ta yayımlanmıştı. OR-Tools 9.15'in Python bağımlılık aralığı daha yeni 7.x'i kabul etmez. Bu nedenle “hiç açık yok” iddiası kurulmaz: danışma taramasının temiz çıkması bu ek sorunu kapsamaz. FDI uygulama kodu dış girdileri `google.protobuf.json_format.ParseDict` ile ayrıştırmaz; mevcut dosya/API yolları CSV, XLSX, JSON ve XSD ile sınırlıdır. Bu, sorunlu üçüncü taraf kod yoluna ilişkin maruziyeti azaltır fakat ileride protobuf JSON girişi eklenirse güvenlik incelemesi gerekir.

Solver sürüm yükseltmesi geçmiş benchmark ve referans kayıtlarının sayısal sonuçlarını geriye dönük değiştirmez. Eski kayıtlar kaynak sürümleriyle tarihsel kanıt olarak kalır; yeni sürüm için yerel test ve yeni main CI kanıtı ayrıca gerekir.
